## 2. 웹사이트 콘셉트

팀원의 역량과 프로젝트, 협업 과정을 하나의 웹사이트에 기록하는 팀 포트폴리오입니다.
방문자가 팀 구성원, 역량, 프로젝트 결과물을 한눈에 확인할 수 있도록 구성합니다.

## 5. 브랜치 전략

| 브랜치 | 용도 |
| --- | --- |
| `main` | 최종 배포 (GitHub Actions 실행) |
| `develop` | 통합 개발 |
| `feat/...` | 신규 기능 개발 |
| `refactor/...` | 코드 개선 |
| `fix/...` | 버그 수정 |

- `develop`에서 작업 브랜치를 만들고, 완료 후 `develop`으로 Pull Request를 작성합니다.
- 배포 시 `develop`에서 `main`으로 PR을 작성하며, PM의 코드 리뷰와 승인 후에만 병합합니다.
- `main`에 직접 푸시하지 않습니다.

# 최종 발표 준비 (D팀)

발표 시간 약 15~20분 / 교수자가 팀원 각자에게 본인 코드의 동작 원리를 질문할 수 있음.
`[ ]` 표시는 개발이 진행되면서 채워 넣을 항목입니다.

## 2. 슬라이드 구성안

1. **표지**: D팀, D = Dev Log, 팀원 이름
2. **제작 목적**: Git/GitHub 협업 경험, 팀 포트폴리오 웹사이트
3. **콘셉트**: D = Dev Log (개발 일지). 다크 테마, 모노스페이스 폰트, 커밋 로그 형태의 카드
4. **사이트 구조**: 메인, 팀 소개, 팀원, 프로젝트(갤러리·상세), 활동 기록, FAQ + 공통 헤더·푸터
5. **시연**: 배포 주소에서 메인 → 각 페이지 이동 → 모바일 화면 → 검색·필터·FAQ 같은 JS 기능
6. **팀원별 담당 기능**: 역할 분담표 (README의 표 활용)
7. **협업 흐름**: Issue → 브랜치 → 커밋 → PR → 리뷰 → develop 병합 → PM 승인 후 main 병합
8. **브랜치 전략**: main / develop / feat·fix·refactor, main 보호 규칙(PR + 승인 필수)
9. **협업 기록 요약**: Issue·PR·리뷰 개수 (협업 기록표 수치는 마지막에 집계) [ ]
10. **병합 충돌 사례**: `index.html` 같은 줄을 수정한 PR #30·#31 → 충돌 발생 → 두 문구를 합쳐 해결 (연습용 충돌임을 밝히고 설명). 팀원 간 실제 충돌이 생기면 그 사례를 추가
11. **배운 점과 개선점**: 개인별 한 줄 [ ]
12. **Q&A**

## 3. 시연 순서 (배포 주소: https://wonchandev.github.io/oss-team-portfolio/)

1. 메인 페이지: 터미널 효과, 메뉴 카드
2. 헤더 메뉴로 각 페이지 이동 (현재 페이지 표시 확인)
3. 팀원 프로필, 프로젝트 갤러리, 프로젝트 상세
4. 검색·필터, FAQ 펼치기·접기
5. 브라우저 창을 줄이거나 모바일 화면으로 전환해 반응형 확인
6. GitHub 저장소: Issues, Pull Requests, 브랜치 목록

시연 전 점검: 모든 링크가 열리는지, 이미지가 깨지지 않는지, 배포 주소가 최신 `main`을 보여 주는지.

## 4. 이원찬 담당 코드 설명 준비

교수자가 질문할 수 있는 부분입니다. 코드 파일을 열어 두고 직접 설명할 수 있어야 합니다.

| 예상 질문 | 답변 요점 |
| --- | --- |
| 공통 헤더·푸터는 어떻게 모든 페이지에 들어가나요? | 각 페이지에 빈 `div`(`#site-header`, `#site-footer`)를 두고, `js/common.js`가 `innerHTML`로 헤더·푸터를 채운다. 메뉴를 바꿀 때 `NAV_ITEMS` 한 곳만 수정하면 모든 페이지에 반영된다. |
| 현재 페이지 표시는 어떻게 하나요? | `location.pathname`에서 파일명을 얻어 메뉴의 `href`와 비교하고, 같으면 `aria-current="page"`를 붙인다. CSS에서 이 속성으로 초록색과 `>` 표시를 준다. |
| 모바일 메뉴는 어떻게 동작하나요? | 햄버거 버튼 클릭 시 `nav`에 `open` 클래스를 토글하고 `aria-expanded`를 갱신한다. 메뉴 항목 클릭·Esc·화면이 넓어질 때 닫힌다. |
| 색상은 어떻게 일관되게 관리하나요? | `:root`의 CSS 변수(`--bg`, `--accent` 등)를 모든 페이지가 `style.css`에서 공유한다. 색을 바꾸려면 변수만 바꾼다. |
| 반응형은 어떻게 구현했나요? | 모바일 우선으로 기본 스타일을 작성하고 `min-width` 미디어 쿼리(768px, 1024px)로 넓혀 간다. `.grid`는 1열 → 2열 → 3열로 바뀐다. |
| 메인 페이지의 타이핑 효과는요? | `js/home.js`가 `setInterval`로 글자를 하나씩 추가한다. 움직임 줄이기 설정(`prefers-reduced-motion`)이면 효과 없이 바로 보여 준다. |
| 왜 JavaScript로 헤더를 넣었나요? | 백엔드가 없는 정적 사이트라 서버 포함(include) 기능이 없어서, 같은 헤더를 페이지마다 복사하지 않고 한 곳에서 관리하기 위해서다. |
| main에 직접 푸시할 수 없나요? | 브랜치 보호 규칙으로 main은 PR과 승인이 있어야 병합된다. |

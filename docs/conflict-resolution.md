# 병합 충돌 해결 기록

과제 안내서 5-6에 따라 병합 충돌이 발생한 상황, 해결 방법, 해결 결과를 기록합니다.
개발 중 팀원 간 실제 충돌이 발생하지 않아, **같은 줄을 서로 다르게 수정하는 두 브랜치를 일부러 만들어 충돌을 일으키고 해결하는 연습**을 진행했습니다. (안내서에서 허용한 방식입니다.)

## 기록 1. 메인 소개 문구 충돌 (연습)

| 항목 | 내용 |
| --- | --- |
| 파일 | `index.html` (메인 페이지 소개 문구 `hero-desc`) |
| 관련 PR | [#30](https://github.com/wonchandev/oss-team-portfolio/pull/30), [#31](https://github.com/wonchandev/oss-team-portfolio/pull/31) |
| 관련 Issue | #3 |

### 발생 상황

같은 `develop` 브랜치에서 갈라진 두 브랜치가 `index.html`의 **같은 줄**을 서로 다르게 수정했습니다.

| 브랜치 | 수정한 문구 |
| --- | --- |
| `feat/hero-copy-a` | 팀원 6명이 함께 만든 코드와 협업 과정을 **한 줄 한 줄** 개발 일지처럼 기록하는 팀 포트폴리오입니다. |
| `feat/hero-copy-b` | 팀원 6명이 **서로의 코드를 리뷰하며 성장하는** 과정을 개발 일지처럼 기록하는 팀 포트폴리오입니다. |

PR #30(A)을 먼저 `develop`에 병합하자, PR #31(B)에 GitHub가 `This branch has conflicts that must be resolved`(충돌 있음, `CONFLICTING`)를 표시해 병합할 수 없게 되었습니다.

### 원인

Git은 같은 줄이 양쪽에서 서로 다르게 바뀌면 어느 쪽이 맞는지 판단할 수 없습니다. B 브랜치는 A가 병합되기 전의 `develop`을 기준으로 만들어졌기 때문에, B의 변경과 `develop`에 새로 들어온 A의 변경이 같은 줄에서 겹쳤습니다.

### 해결 방법

1. B 브랜치에서 최신 `develop`을 가져와 병합했습니다.
   ```bash
   git fetch
   git checkout feat/hero-copy-b
   git merge origin/develop
   # CONFLICT (content): Merge conflict in index.html
   ```
2. `index.html`에 표시된 충돌 구간을 열었습니다.
   ```text
   <<<<<<< HEAD                      (B 브랜치의 내용)
   팀원 6명이 서로의 코드를 리뷰하며 성장하는 과정을 개발 일지처럼 기록하는 팀 포트폴리오입니다.
   =======
   팀원 6명이 함께 만든 코드와 협업 과정을 한 줄 한 줄 개발 일지처럼 기록하는 팀 포트폴리오입니다.
   >>>>>>> origin/develop            (A의 내용, 이미 병합됨)
   ```
3. 한쪽을 버리지 않고 **두 문구의 의도를 모두 살려 하나로 합쳤고**, `<<<<<<<`, `=======`, `>>>>>>>` 표시를 모두 지웠습니다.
   ```text
   팀원 6명이 함께 만든 코드와, 서로의 코드를 리뷰하며 성장하는 과정을 한 줄 한 줄 개발 일지처럼 기록하는 팀 포트폴리오입니다.
   ```
4. 충돌 표시가 남지 않았는지 확인한 뒤 커밋하고 푸시했습니다.
   ```bash
   git add index.html
   git commit -m "merge: develop 병합 및 메인 소개 문구 충돌 해결"
   git push origin feat/hero-copy-b
   ```

### 해결 결과

- PR #31의 충돌이 사라져 `develop`에 병합되었습니다.
- 병합된 `develop`의 `index.html`에는 두 브랜치의 의도(함께 만든 코드, 서로 리뷰하며 성장, 한 줄 한 줄 기록)가 모두 반영되어 있습니다.
- 충돌 표시 문자가 남아 있지 않고, 메인 페이지가 정상적으로 표시됨을 확인했습니다.

### 배운 점

- 충돌은 두 사람이 같은 줄을 고칠 때 생기므로, 작업 전에 어느 파일·부분을 고칠지 팀원과 공유하면 줄일 수 있습니다.
- 페이지별로 파일을 나누고 전용 CSS를 따로 두는 현재 구조(`css/페이지이름.css`)가 충돌을 줄여 줍니다.
- 충돌을 해결할 때는 한쪽을 무작정 선택하지 말고 두 변경의 의도를 모두 확인한 뒤 합쳐야 합니다.
- 병합 전에 `develop`을 먼저 가져와 최신 상태에서 작업하면 충돌을 미리 발견할 수 있습니다.

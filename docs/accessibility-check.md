## 3. 발견 사항 및 개선

### 11월 21일: 본문 바로가기와 필터 초기화

**본문 바로가기 (`js/common.js`)**

404 페이지에서는 `href="#main"`이 base 주소를 기준으로 해석되어 다른 문서로 이동할 수 있었습니다. 현재 문서 주소 뒤에 `#main`을 붙이도록 수정했습니다. 쿼리 문자열은 유지하고 기존 해시는 교체합니다.

수정 후 404와 깊은 오류 주소에서 본문 바로가기를 실행했을 때 현재 페이지에 머무는 것을 확인했습니다.

**필터 초기화 후 초점 (`js/filter.js`)**

초기화하면 초기화 버튼이 숨겨지므로, 키보드 사용을 이어갈 수 있도록 검색창의 `focus()`를 호출하도록 수정했습니다.

수정 후 키보드로 초기화 버튼을 실행하고 마우스를 사용하지 않은 상태에서 검색창에 다시 입력할 수 있는 것을 확인했습니다.

### 11월 22일: FAQ 초점 표시와 활동 선택 상태

**FAQ 초점 테두리 (`css/faq.css`)**

FAQ 카드의 `overflow: hidden` 때문에 버튼 바깥의 초점 테두리가 잘릴 수 있는 구조를 확인했습니다. `.faq-question:focus-visible`에 `outline-offset: -3px`을 적용하여 테두리를 버튼 안쪽에 표시하도록 수정했습니다.

평상시 디자인과 답변 펼치기·접기 동작은 유지했습니다. 수정 후 FAQ를 키보드로 사용했을 때 동작에 이상이 없었습니다.

**활동 목록의 선택 상태 (`js/activities.js`)**

기존에는 선택된 활동을 클래스와 색상으로만 표시했습니다. 버튼에 `aria-controls`와 `aria-pressed`를 추가하고, 항목 선택 시 시각적 표시와 선택 상태가 함께 바뀌도록 수정했습니다.

기존 버튼과 본문 표시 방식은 유지했습니다. 수정 후 항목을 선택하면 해당 내용이 표시되는 것을 확인했습니다.

## 5. 이미지 및 글자 색 대비

### 이미지 대체 텍스트

현재 9개 페이지의 정적 HTML에 본문 img 요소가 없고, 활동 기록 데이터의 이미지 경로도 모두 비어 있습니다. 홈의 터미널 예시에는 `role="img"`와 설명용 `aria-label`이 있으며, 장식 요소는 `aria-hidden`으로 처리되어 있습니다. 이미지가 추가되면 내용에 맞는 대체 텍스트를 다시 확인해야 합니다.

### 글자 색 대비

CSS에 선언된 주요 단색 글자·배경 조합 14개를 계산했으며, 모두 4.5:1 이상이었습니다.

| 본문 #c9d1d9 | 12.26:1 | 11.21:1 |
| 보조 #8b949e | 6.15:1 | 5.62:1 |
| 강조 #3fb950 | 7.45:1 | 6.81:1 |

초록 버튼 배경 #3fb950에서 글자 #04130a는 7.50:1, #0d1117은 7.45:1입니다. 이 수치는 선언된 단색 조합 기준이며, 투명 배경·그라데이션·컨트롤 경계의 전체 상태까지 측정한 결과는 아닙니다.
